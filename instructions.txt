🔒 SECURITY CONFIGURATION (CRITICAL FOR PRODUCTION)
================================================================================

Development Setup (Local Testing):
--------
No special security configuration needed for local development.
Default settings include:
  - Debug mode enabled (auto-reload on code changes)
  - Dev-safe secrets (clearly marked as development-only)
  - HTTP allowed (no HTTPS required)
  - Rate limiting enabled (5/minute login, 5/hour registration)

Production Deployment (CRITICAL):
--------
Before deploying to production, you MUST configure security settings:

1. Create .env file from template
   cp .env.example .env
   cp .env.production.example .env  (for production)

2. Generate strong secrets (CRITICAL)
   python -c "import secrets; print(secrets.token_urlsafe(32))"
   - Generate 2 values: SECRET_KEY and SECURITY_PASSWORD_SALT
   - Update both values in .env
   - DO NOT use default "dev-*" values in production

3. Set environment to production
   FLASK_ENV=production
   FLASK_DEBUG=0

4. Configure HTTPS/TLS
   FORCE_HTTPS=1  (requires SSL certificate on server)
   SESSION_COOKIE_SECURE=1

5. Configure email (SMTP)
   MAIL_SERVER, MAIL_PORT, MAIL_USERNAME, MAIL_PASSWORD
   (Use app-specific password for Gmail)

6. Review full security guide
   Read: PHMS/SECURITY.md (comprehensive security documentation)

Security Features Implemented:
  ✓ Rate limiting (5 login attempts/min, 3 password resets/hour)
  ✓ CSRF protection (Flask-WTF with 1-hour token validity)
  ✓ Secure cookies (HttpOnly, SameSite, Secure flags in production)
  ✓ Password hashing (Werkzeug security)
  ✓ HTTPS enforcement (HTTP → HTTPS redirect in production)
  ✓ HSTS headers (1-year browser HTTPS enforcement)
  ✓ Security headers (CSP, X-Frame-Options, X-XSS-Protection)
  ✓ OTP-based password reset (6-digit code, 10-minute expiry)

For detailed security configuration, see: PHMS/SECURITY.md

AUTOMATED SCHEDULER JOBS (via start.py)
================================================================================
When you run start.py, APScheduler automatically starts 4 background jobs:

Job 1: Daily Medication Log Creation (00:00 UTC)
- Creates pending medication logs for all active prescriptions
- Runs every midnight automatically

Job 2: Medication Reminders (Every 60 seconds)
- Checks for upcoming doses (15-minute advance warning)
- Sends email alerts for critical medications
- Creates notification alerts

Job 3: Grace Period Management (Every 60 seconds)
- Marks pending logs as 'missed' after 30-minute grace period
- Sends email alerts for missed critical medications

Job 4: Consecutive Missed Detection (23:59 UTC)
- Detects 3+ consecutive missed days
- Sends critical warning emails to users
- Runs daily at 11:59 PM

To manually control scheduler:
    from scheduler_config import SchedulerSetup
    SchedulerSetup.init_scheduler(app)
    SchedulerSetup.init_medication_logs()

DATABASE SCHEMA
================================================================================
SQLite database with 7 tables:
1. user                 - User accounts (username, email, password, bmi)
2. health_data          - Health records (vitals + 3 health scores)
3. medication           - User prescriptions (frequency, dosage, is_critical)
4. medication_log       - Daily tracking (status, scheduled_time, actual_time)
5. medicine             - Master catalog (name, category, stock)
6. alert                - Notifications (title, message, category, severity)
7. password_reset_otp   - Time-limited OTP codes (expires in 10 minutes)

Relationships:
- User → HealthData (1:N, cascade delete)
- User → Medication (1:N, cascade delete)
- User → Alert (1:N, cascade delete)
- User → PasswordResetOTP (1:N, cascade delete)
- Medication → MedicationLog (1:N, cascade delete)
- Medicine → Medication (1:N, restrict delete)

TROUBLESHOOTING
================================================================================

Issue 1: "No module named 'models'"
Solution:
- Ensure you're in PHMS directory: cd PHMS
- Activate venv: .\venv\Scripts\Activate.ps1
- Verify __init__.py exists in models/ and controllers/

Issue 2: Database not found / Table doesn't exist
Solution:
- Run migrations: flask db upgrade
- Or use start.py for automated setup
- Check instance/phms.db file exists

Issue 3: Scheduler not running
Solution:
- Use start.py instead of app.py directly
- Check console for "Scheduler initialized" message
- Verify APScheduler installed: pip show APScheduler

Issue 4: Email notifications not sending
Solution:
- Configure MAIL_* settings in config.py
- Use Gmail App Password (not account password)
- Check firewall/antivirus blocking SMTP port 587
- Test with: from flask_mail import Message

Issue 5: ModuleNotFoundError
Solution:
- Activate venv: .\venv\Scripts\Activate.ps1
- Reinstall dependencies: pip install -r requirements.txt
- Check Python version: python --version (3.8+ required)

Issue 6: Port 5000 already in use
Solution:
- Change port in app.py: app.run(port=5001)
- Or kill process: netstat -ano | findstr :5000

Issue 7: ML prediction fails
Solution:
- Verify ml/trained_models/ contains:
  * phms_classifier_v6.pkl
  * phms_regression_v6.pkl
  * label_encoder_v6.pkl
- Check console for ML loading errors

Issue 8: Permission denied on venv activation (PowerShell)
Solution:
- Run PowerShell as Administrator
- Or use Command Prompt instead: venv\Scripts\activate

Issue 9: "CRITICAL SECURITY ERROR: Production Secret Key Not Configured"
Solution:
- Generate SECRET_KEY: python -c "import secrets; print(secrets.token_urlsafe(32))"
- Generate SECURITY_PASSWORD_SALT: python -c "import secrets; print(secrets.token_urlsafe(32))"
- Add both to .env file in project root
- Only occurs when FLASK_ENV=production
- See PHMS/SECURITY.md for detailed instructions

Issue 10: Rate limiting blocking legitimate requests
Solution:
- Increase limits in .env: RATELIMIT_AUTH_ATTEMPTS=10 per minute
- Switch from memory to redis for distributed rate limiting
- Use whitelist IP addresses if behind proxy
- See PHMS/SECURITY.md for rate limit configuration

Issue 11: "Secure cookies enforced" error in development
Solution:
- Set SESSION_COOKIE_SECURE=0 in .env (development only)
- Or enable HTTPS and set SESSION_COOKIE_SECURE=1
- Only enforced in production (FLASK_ENV=production)

Issue 12: CSRF token errors on forms
Solution:
- Verify csrf_token() macro is in HTML templates: {{ csrf_token() }}
- Check X-CSRFToken header in JavaScript requests
- Increase WTF_CSRF_TIME_LIMIT if needed: 3600 (1 hour)
- Clear browser cookies and try again
- Or: Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

Issue 9: start.py fails to initialize
Solution:
- Check migrations are up to date: flask db upgrade
- Verify database permissions in instance/ directory
- Review console error messages for specific issues
