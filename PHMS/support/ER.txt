NOTES
--------------------------------------------------------------------------------
- Field names above intentionally match model names exactly (for migration safety).
- `medication.frequency` is INTEGER in current model.
- `health_data` keeps single `blood_pressure` field (FLOAT).
- `alert` has `medication_log_id` and no `medication_id` FK column.
- `password_reset_otp` uses `user_email` and not `user_id`.
- `smartwatch_account` and `smartwatch_sync_state` support multi-provider wearable integration.
- `smartwatch_sync_state.provider` is denormalized from `smartwatch_account` for faster queries.
- `health_data` deduplication uses both source ID (provider-native) and ingestion fingerprint (content hash).
- `user.is_admin` flag controls role-based features (admin dashboard, user management).
- `otp_code` is stored hashed (argon2) at VARCHAR(255) length, not plaintext 6-digit.
